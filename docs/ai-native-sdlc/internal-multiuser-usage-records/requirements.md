# 需求文档：hydroZagent 内网多用户接入与使用记录

> 状态：**需求已确认，待技术设计** — 已吸收第一至四轮评审意见
> 最后更新：2026-09-01
> SDLC 位置：本文档是同目录 `intent.md` 的**详细需求输入材料**；待 `intent.md` 被 accept 后，据此转化为正式 `spec.md`（技术设计）。它不是 Intent 的下游产物，而是先于 Intent 迭代成形、供 Intent 提炼问题与约束的来源材料。

## 1. 项目背景

当前"浙水智能体"（hydroZagent）**已具备本地 Agent、项目与会话管理、文档处理与数据分析等核心能力，但尚未达到单位级多用户部署要求**：形态为 Windows 优先的 Electron 桌面工作台，Agent 运行时在本机执行、直接操作本机文件，目前缺少面向单位内多同事的**身份管理**、**使用准入**与**使用记录**能力。

为推动其在单位内部试用与推广，采用**"胖客户端 + 服务端模型代理与使用记录服务"**架构：

- 单位内每位同事在**自己的电脑上安装并运行 hydroZagent 桌面应用**，Agent 在本机执行、处理本机文件（无需上传文件到服务器，谁的文件谁处理）。
- 在**单位内网部署一台 Linux 服务器**，运行一个**新建的、独立的纯后端程序**（无图形界面），承担四项职责：**账号与登录鉴权**、**模型请求代理**、**用户分组管理**、**采集并留存**使用记录。
- 客户端**不直连**大模型，也**不持有模型密钥**；所有模型调用携带用户令牌、经服务器代理转发至**单位内网自建的模型推理服务**（已就绪，OpenAI 兼容 API）。**受管模型请求/响应与集中使用记录仅在单位内网流转**（浏览器/Shell/扩展的联网见 §4.5/D16）。

## 2. 总体架构

```text
每位同事的电脑 (Windows；macOS 见 P2)
  └─ hydroZagent 桌面应用（本地安装 / 本地运行 Agent，操作本机文件）
        ├─ 启动强制登录（严格在线：连不上服务器则禁用 Agent）
        ├─ 模型调用 ─┐（携带用户令牌，不含模型密钥；受管模式锁定指向）
        └─ 会话上报 ─┤（携带用户令牌）
                     ▼
内网服务器 (Linux，新建独立纯后端，无 GUI)
  ├─ 账号服务：注册 / 登录 / 令牌签发校验 / 角色（user·admin）
  ├─ 模型代理：校验令牌 + 有效同意 → 转发内网模型服务 → 回传（★门禁在此真实生效）
  ├─ 记录服务：从令牌解析用户、从库取分组；事件/会话/轮次 ID + 幂等接收
  ├─ 管理端：简单 Web 管理界面（admin 角色鉴权）
  └─ 存储：数据库（用户 / 分组 / 关联 / 模型代理调用日志 / 客户端使用记录 / 同意）；须配置期限 + 可删除
                     │
                     └─► 内网自建模型推理服务（已就绪；★仅接受来自代理服务器的请求）
```

## 3. 关键设计决策（已确认）

| # | 决策 | 选定方案 | 理由 / 影响 |
| --- | --- | --- | --- |
| D1 | 登录作用 | **准入门禁** | 由 D2 服务端代理真正保证，非可绕过的客户端检查 |
| D2 | 模型鉴权 | **服务端代理模型请求** | 客户端不持密钥、不直连。**可信边界：模型准入与代理调用日志可信；客户端上报的输入/最终回复属尽力采集（见 D3），非防篡改审计**。代价：服务器进入热路径、须在线、承担网关角色 |
| D3 | 采集颗粒度 | 用户输入 + 最终助手回复 + 元数据（P0 边界见 §5.1） | 定位为**试用分析（尽力采集）**，非防篡改审计 |
| D4 | 采集可信性 | 服务端从令牌解析用户、从库取分组；事件/会话/轮次 ID + 幂等 | 不信任客户端提交的身份/角色 |
| D5 | 在线模式 | **P0 严格在线** | 连不上服务器则禁用 Agent。"离线"仅指记录接口补传，非离线运行（§8/D2） |
| D6 | 用户-分组 | 多对多；记录打**服务端接收时**分组快照（不可变，**P0 可为空**） | 见 D17 分期 |
| D7 | 注册与身份 | **自助注册 + 标注非实名 + 注册限流 + 账号名唯一 + 保留名称限制** | 只能防止账号重名，不能验证真实人员或阻止首个注册者冒用姓名；记录只代表**自报账号、不作实名审计**。网络层兜底（内网仅本单位可达），责任归属较弱为已知取舍 |
| D8 | 管理端鉴权 | 统一账号体系 + 角色标记（user/admin） | 首个管理员由服务器配置创建；管理端按 admin 校验 |
| D9 | 保存期限 | **上线前必须配置明确期限**；支持自动清理与管理员删除 | 不以"长/不限"作为终态；具体值见 §10 |
| D10 | 局域网 Web 服务 | P0 受管发行版强制关闭并锁定（§4.3） | 消除认证旁路 |
| D11 | 平台 | P0 仅 Windows，macOS 纳入 P2 | mac 排期需 Spike 确认（§4.4） |
| D12 | 受管模式 | 锁定模型指向、禁止其他 Provider、启动边界强制（§4.5） | 仅改 UI 挡不住本地配置绕过 |
| D13 | 本地隔离 | **P0 声明"一机一账号"为环境假设与已知风险，不宣称客户端隔离** | 真正按账号隔离目录放 P2（§4.2/§10） |
| D14 | 撤回同意 | 停止采集 + 旧记录不立即删除 | 采集是使用前提，撤回即停使用权（重新同意恢复）；旧记录继续按统一保存期限自动清理，也可由 admin 提前删除；不自动停用账号 |
| D15 | 模型协议 | OpenAI 兼容 API | 代理据此实现流式/工具调用/取消/错误映射 |
| D16 | 不出网范围 | P0 仅覆盖模型调用与集中记录 | 浏览器/Shell/扩展联网不在应用强管范围（§4.5/§6） |
| D17 | 分组分期 | **P0 不启用分组（快照可空）；分组表/分配/统计从 P1** | 消除 P0/P1 分组范围冲突 |
| D18 | 上报重试 | **P0 有界进程内重试；P2 加密持久化 Outbox** | P0 不保证应用退出后续传；P2 支持跨重启补传、容量限制、回执删除与幂等去重 |

## 4. 功能需求

### 4.1 服务端（新建，Linux 纯后端程序）

- **账号与生命周期**：自助注册（注册限流 + 账号名唯一 + 保留名称限制）、登录、令牌签发/校验；**退出登录**时服务端撤销当前登录会话及其刷新令牌，**注销账号**时停用账号并撤销全部服务端令牌。使用记录与同意记录不因退出或注销立即删除，继续按统一保存期限清理，也可由 admin 提前删除。密码以**加盐单向哈希存储（Argon2id / scrypt / bcrypt）**，非可逆加密。用户带角色（`user`/`admin`），首个管理员由服务器配置创建。客户端凭证清理见 §4.2，账号安全见 §6。
- **模型代理**：接收携带用户令牌的模型请求，**校验令牌 + 校验有效同意记录**后转发内网模型服务（**OpenAI 兼容**）并回传；模型访问凭证**仅存于服务器**。须支持：流式响应、工具调用、**取消请求（同步终止上游、不产生悬挂请求）**、超时、最大请求体、错误映射、并发限制、用户配额。作为单点入口，**P0 即具备基础存活检查、进程守护与故障告警**（指标看板/容量趋势等高级监控见 P2）。*内网模型服务须在网络层限制为仅接受代理服务器请求。*
- **模型代理调用日志（可信）**：每次代理调用由服务端生成调用 ID，并记录从令牌解析的用户 ID、模型、开始/结束时间、状态、错误码、Token 用量（上游可提供时）与耗时；**不记录请求正文、响应正文及敏感请求头**。
- **客户端使用记录接口（尽力采集）**：**身份从令牌解析、分组从库获取，不信任客户端提交**；每条记录带全局事件 ID、会话 ID、轮次 ID，**幂等接收**（去重）并回执。一个用户轮次可关联零到多条模型代理调用日志，须明确区分两类记录的可信等级。
- **分组**（P1 起，见 D17）：多对多归类；P1 提供 Web 管理、按组统计与导出；P0 分组快照可为空。
- **管理端（Web 管理界面，P1）**：admin 按用户/分组/时间检索、统计、导出、删除；按 `role === admin` 鉴权。**P0 提供管理员 CLI 或受保护接口**用于建号/改角色/删记录。
- **数据存储**：用户表〔含 role〕、分组表、用户-分组关联表、`model_proxy_calls`（模型代理调用日志）、客户端使用记录表、轮次-模型调用关联表、同意记录表。

### 4.2 客户端（在现有 hydroZagent 桌面应用中新增）

- **登录门禁（严格在线）**：启动/使用 Agent 前登录；连不上服务器或令牌失效即禁用 Agent，明确提示，不静默失败。
- **凭证与账号操作**：访问令牌和刷新令牌保存到 **Windows Credential Manager 等系统安全存储**，不得写入 `settings.json`、日志或普通本地存储；退出登录时调用服务端撤销当前登录会话并清除本地令牌，注销账号成功后清除全部本地业务凭证。
- **模型调用改造**：所有模型请求改为携带用户令牌、发往服务器模型代理；**移除客户端内置模型密钥与直连逻辑**。
- **会话上报（尽力采集，D18）**：上报用户输入与最终助手回复 + 元数据。P0 仅在当前进程内执行有限次数的指数退避重试，超过上限后给出用户可见提示，**不保证应用退出后续传**；P2 增加加密持久化 Outbox。
- **本地隔离约束（D13，已知风险）**：hydroZagent 的项目/会话/JSONL 存于 Windows 系统用户目录（`~/.pi`、`~/.dsh`、userData），非按业务账号隔离。**P0 明确为环境假设："一个 Windows 系统用户 ↔ 一个 hydroZagent 业务账号"**，并作为已知风险告知用户不要在同一 Windows 用户下切换业务账号。**P0 不宣称客户端已保证隔离**；按账号隔离目录列入 P2（§10）。
- **知情同意**：见 §5.4。

### 4.3 局域网 Web 服务的处置（消除认证旁路）

现有桌面应用内置默认监听 `0.0.0.0:8765`、**无鉴权、允许任意来源**发起对话/读会话/执行操作的局域网 Web 服务（默认关闭，但用户可开启）。

- **P0**：受管发行版**强制关闭并锁定**该入口（用户不可自行开启）。
- **后续（可选）**：如确需内网共享，须接入同一套登录、权限与审计体系后方可开放。

### 4.4 分发与运维

- 客户端安装包分发（`desktop:dist`）与更新机制。
- **平台支持**：P0 仅 Windows；macOS 纳入 P2。代码层基本就绪（已有 mac 构建配置与平台分支），主要成本为须在 Mac 上构建、原生依赖 darwin 变体（node-pty/sharp）、Apple 开发者账号 + 签名/公证、arm64 优先。**具体排期需通过"Mac 构建与签名 Spike"确认后写入实施计划，不作为需求事实。**
- 服务器部署、备份、日志与监控（P0/P2 范围见 §6、§8）。

### 4.5 受管模式（Provider 锁定，D12/D16）

现有项目支持自定义 Provider、baseUrl、API key、OAuth 与配置迁移（`providerMigrationService`、`ConfigManager`）。仅改界面默认地址不足以约束，受管发行版必须：

- **固定模型代理地址**，客户端不可改指向其他端点；
- **禁止添加、迁移或选择其他 Provider**；
- **忽略本机既有 `auth.json` / `models.json` 中的非受管模型配置**；
- 在**主进程 / Agent 启动边界强制**执行，不能只隐藏界面；
- **不出网范围（D16）**：P0 仅保证受管模型请求/响应与集中记录不出网。浏览器、Shell、扩展等工具的联网**不在应用强管范围**，作为风险告知；若要覆盖须配合**网络出口管控**（防火墙/代理策略，属运维层，单靠应用无法保证）。

## 5. 数据与采集规则

### 5.1 采集边界与记录结构（P0）

- **客户端使用记录**：用户输入正文、最终助手回复、元数据（客户端产生时间、服务端接收时间、用户〔令牌解析〕、分组快照〔接收时，**P0 可为空**〕、任务类别、模型、事件/会话/轮次 ID、客户端版本、设备 ID、**模型调用 ID 列表或关联关系〔零到多条〕**）。
- **模型代理调用日志**：服务端调用 ID、用户〔令牌解析〕、模型、开始/结束时间、状态、错误码、Token 用量（可得时）与耗时；该日志不包含请求/响应正文。
- **关联关系**：一个客户端轮次可能在工具调用循环中触发多次模型调用，也可能在实际发起模型调用前终止，因此须支持**一轮关联零到多条模型代理调用日志**，不能以单个“模型请求 ID”建模。
- **P0 默认不采集**（各自单独决策后再启用）：图片/附件内容、系统提示词、思考过程、工具参数、命令输出、错误详情、流式中间片段。
- **记录终态**：每轮保存状态 `completed` / `aborted` / `error`；对被中止、模型报错、无最终文本、多次工具调用的轮次也落库（最终文本可为空），保证可统计。
- **注意**：即使"不上传文件"，用户仍可能把文件正文粘贴进输入——输入正文属采集范围，须在知情同意中说明。

### 5.2 临时会话（原"匿名会话"）语义与 UI

现有匿名会话仅存内存、不写本地会话目录。在登录门禁下仍归属登录用户并上报，故：

- 记录仍上报，元数据标记 `anonymous=true`；
- **界面名称改为"临时会话（不保存在本机，但使用记录仍会上报）"**，避免"匿名"误导。

### 5.3 多对多分组归属与统计（接收时快照，D6）

- 记录的分组以**服务端接收该记录时**用户所属的全部分组为快照（不可变，P0 可为空）。
- 用户调组后，历史记录保留其快照，不追溯变更。
- **P1 统计口径**：一条记录计入其快照的全部分组，**各组直接相加会重复计数，须明确去重口径**；分组增加 `department` / `trial_batch` 等**类型维度**，不同维度不混算。

### 5.4 知情同意（客户端展示 + 服务端强制）

- 首次登录展示告知并确认；**拒绝则无法使用**。
- **服务端在模型调用前校验有效同意记录**（客户端弹窗不可信）；告知文本更新后对旧版本同意返回 `consent_required`，强制重新同意。
- 记录**同意版本、同意时间、客户端版本、告知文本版本**。
- **撤回同意（D14）**：停止采集新轮次；撤回即停止 Agent 使用权（重新同意恢复）；旧记录不立即删除，继续按统一保存期限自动清理，也可由 admin 提前删除；不自动停用账号。

### 5.5 历史会话与回传边界

- **仅采集用户同意后、受管版本产生的新轮次**；不自动回传安装前的历史会话。
- 恢复旧会话时，旧内容**仅作为模型上下文经代理转发，不进入集中使用记录**。

## 6. 非功能需求与合规

- **数据流转范围**：受管模型请求/响应与集中使用记录仅在内网流转；浏览器/Shell/扩展的联网不在 P0 保证范围（D16）。
- **静态数据与密钥保护**：数据库/磁盘**静态加密**、**备份加密**、文件权限最小化；模型服务密钥、令牌签名密钥等经**环境变量或密钥管理设施注入**，**不得进入代码仓库与日志**。
- **代理/日志脱敏**：模型代理、反向代理与应用日志**不得记录请求体、响应体、令牌及敏感请求头**；仅持久化 §5.1 允许字段。
- **账号安全**：唯一性、密码复杂度、登录限流、失败锁定、密码重置、账号停用、令牌有效期/刷新/撤销（撤销/停用后在线客户端规定时间内失效）、传输 HTTPS、管理操作审计、**注册接口限流与异常注册审计**。
- **权限最小化**：记录仅 admin 可查/导出/删除；普通用户不可见他人记录。
- **凭证安全**：密码加盐单向哈希；令牌有有效期；Windows 客户端通过系统安全存储保存令牌，不写入 `settings.json`、日志或普通本地存储；客户端不含模型密钥。
- **保存与退出机制**：上线前配置明确期限、自动清理、管理员删除、用户注销处理、备份同步过期、删除/导出操作审计。
- **运维范围**：**P0** — 基础存活检查、进程守护、故障告警；**P2** — 指标看板、容量趋势、完整备份恢复演练、高级监控。
- **容量与验收指标（技术设计阶段据实际规模定稿）**：并发用户数、日均轮次、单条最大上报体积、数据库年增长、备份周期与 RPO/RTO、接口响应时间目标。
- **可用性**：服务器不可达时客户端明确、安全地禁用，不静默失败。

## 7. 权限模型（P0）

| 角色 | 使用 Agent | 查看自己记录 | 查看/导出/删除全部记录 | 建号/改角色/管分组 |
| --- | --- | --- | --- | --- |
| user | ✅ | （P0 暂不提供自查界面） | ❌ | ❌ |
| admin | ✅ | ✅ | ✅ | ✅ |

- P0 只设 user/admin；"授权人员"即 admin。后续按需扩展分组管理员、审计员（只读+导出、不可删）等（§10）。

## 8. 分期里程碑（先 ship，再 iterate）

| 阶段 | 目标 | 交付物 |
| --- | --- | --- |
| **P0 最小可用** | 登录门禁 + 模型代理 + 尽力采集 + 受管锁定 | 服务端：账号/登录/令牌（注册限流+账号名唯一+保留名称限制）、模型代理（含同意校验、取消、存活检查/进程守护/告警）、可信模型代理调用日志、客户端使用记录接口（令牌解析身份+幂等）、管理员 CLI、数据库、静态/密钥保护；客户端：登录门禁（严格在线）、系统安全存储令牌、退出/注销清理、模型改走代理、受管 Provider 锁定、会话上报（有界进程内重试）、知情同意；锁闭局域网 Web 服务。**分组不启用（快照可空）** |
| **P1 分组与查询** | 分组与 Web 管理端 | 分组表/分配、多对多接收时快照、按组统计（去重口径 + 类型维度）、检索/导出/删除、简单 Web 管理界面 |
| **P2 运维与硬化** | 记录补传、隔离、分发、备份、监控、macOS | **加密持久化 Outbox**（模型代理可用、仅记录接口暂失败时跨重启缓冲/重试/去重；具备容量限制、确认回执后删除与退出清理；非离线运行 Agent）、**按账号隔离本地目录**、客户端分发更新、备份恢复演练、高级监控、macOS 构建/签名 |

> **P2"离线"澄清**：D2 要求模型必须经代理、D5 规定服务器不可达即禁用，故**不存在离线运行 Agent**。P2 的"补传"仅指记录接口暂失败时的缓冲重传。真正离线需本地模型或直连，与 D2 冲突，不做。

### P0 验收要点

1. 未登录/离线无法调用模型；伪造身份的上报被拒；重复上报去重。
2. 未同意当前告知版本时，服务端拒绝模型调用（返回 `consent_required`）。
3. 安装包与配置目录中不存在可直接调用模型的共享密钥。
4. 受管模式无法添加或切换到其他模型 Provider（含忽略本机既有 auth/models 配置）。
5. 模型服务拒绝非代理服务器来源的请求。
6. 代理及应用日志不记录模型请求正文与令牌。
7. 只采集同意后的新轮次，不自动上传历史记录。
8. 令牌撤销 / 账号停用后，在用客户端在规定时间内失效。
9. 流式请求取消后上游同步终止，不产生悬挂请求。
10. 关闭局域网 Web 旁路。
11. 注册接口具备限流、账号名唯一性检查、保留名称限制与异常注册审计；记录明确标注为"自报账号、非实名"，不宣称系统能够验证真实人员身份。
12. P0 分组快照为空时行为正常、不报错。
13. 数据库静态数据、模型服务密钥与令牌签名密钥不以明文文件方式暴露；P0 如生成备份，备份必须加密，完整备份恢复演练按 P2 验收。
14. 模型代理调用日志与客户端使用记录能明确区分可信等级；调用日志不含正文，并支持一个客户端轮次关联零到多次模型调用。
15. 令牌仅保存于系统安全存储；退出登录会撤销当前登录会话并清除本地令牌，注销账号会撤销全部服务端令牌并清除本地凭证。
16. P0 上报失败仅执行有界进程内重试，超过上限明确提示；不会被描述或误验收为跨重启可靠补传。

> **一机一账号（D13）为 P0 环境假设与已知风险，不列为验收承诺**——P0 不宣称客户端已保证会话隔离；真正隔离在 P2 验收。

## 9. 与仓库现状的衔接

- 服务端为**新建独立后端**，**不复用 `packages/server`**（实验性会话通信组件，无独立服务入口）。须明确新服务端应用目录与数据库边界。
- 现有用量统计仅读 Pi/DSH 日志、按会话/模型/项目聚合，**不能提供用户级记录**；须新增服务端 `model_proxy_calls` 可信调用日志、客户端轮次采集点及二者的一对多关联模型。
- 客户端改造涉及 hydroZagent 桌面应用，遵循其 `AGENTS.md` / `HYDRO.md`；受管模式策略须落在主进程/Agent 启动边界（§4.5）。
