# Intent: hydroZagent 内网多用户接入与使用记录

## Problem

hydroZagent 目前是**单机、单用户**的桌面工作台：Agent 运行时在本机执行、直接操作本机文件，只供开发者个人调试。要在单位内部推广试用，缺三样支撑多用户部署的能力，且现状还带一个安全旁路：

- **没有身份与准入**：任何拿到安装包的人都能直接使用，无法区分"谁在用"，也无法限制使用范围。
- **没有使用记录**：无法沉淀真实业务场景的问答数据、评估回答质量、支撑后续优化。现有用量统计只读 Pi/DSH 日志、按会话/模型/项目聚合，**给不出用户级记录**。
- **模型密钥无从管控**：若让客户端各自直连大模型，密钥要么内置共享（可被提取）、要么逐人分发（难管控）。
- **既有认证旁路**：桌面应用内置一个默认监听 `0.0.0.0:8765`、**无鉴权、允许任意来源**的局域网 Web 服务（默认关闭但用户可开启），可发起对话、读会话、执行会话操作——一旦开启即绕过任何桌面侧准入。

同时有一个不能被破坏的现状：hydroZagent 的价值在于 **Agent 操作用户本机文件**。任何"集中部署到服务器"的方案如果让用户改为操作服务器文件、或需要上传文件，都会破坏这一核心体验。

## Proposed outcome

单位内每位同事在**自己的电脑**上安装运行 hydroZagent（Agent 仍在本机、操作本机文件）。目标按阶段划分，边界清晰：

**P0（本次交付核心，Success measures 只验收这一层）**

1. **必须登录才能使用**，且门禁**无法通过改客户端或本地配置绕过**——未通过身份与准入的请求，模型侧根本调不动。
2. 每次使用的用户输入与最终回复被**尽力采集、失败对用户可见、采集结果可观测**，在**用户知情同意**前提下集中留存，可供质量分析与数据沉淀。
3. **受管模式锁定**（模型只能走服务端代理），**数据不出单位内网**，关闭局域网 Web 旁路。
4. 集中侧作为一个**新建的独立 Linux 纯后端程序**运行，不承载用户文件与算力；**P0 优先支持单节点部署，资源规格在容量评估后确定**。

**P1（后续交付）**：用户**分组**，管理员按用户/分组**检索、统计、导出、删除**，提供简单 **Web 管理界面**。

**P2（长期愿景）**：**跨重启的可靠持久补传**、按业务账号**隔离本地目录**、**macOS** 发行、运维硬化。

> 说明：分组、查询、统计、导出属 **P1**，不在本次 P0 交付范围；本 intent 的 Success measures 仅覆盖 P0，P1/P2 为方向性目标，待各自阶段细化。

## Affected users and systems

- **用户**：单位内使用 hydroZagent 的同事（普通 user）与管理员（admin）。
- **hydroZagent 桌面应用**（`apps/desktop`）：新增登录门禁、模型调用改走服务端代理、受管模式（锁定模型指向）、会话上报、知情同意，并锁闭局域网 Web 服务；受管策略须在主进程/Agent 启动边界生效，不能只改界面。
- **新建独立后端**（不复用实验性的 `packages/server`）：账号、模型代理、使用记录、分组、管理端、存储。
- **内网自建模型推理服务**（已就绪，OpenAI 兼容）：须在网络层限制为仅接受代理服务器请求。
- **运维**：Linux 服务器部署、静态数据/密钥保护、备份与基础监控告警。

## Constraints

已在需求收敛中锁定、下一阶段（spec）必须遵守的**业务与安全硬约束**（接口契约、表结构、错误码、令牌与取消的具体实现留给 spec.md）：

- **门禁靠架构保证，不靠客户端自觉**：客户端不持模型密钥、不直连模型；模型调用经服务端代理，代理校验身份与有效同意后才转发。
- **可信边界分级**：模型准入与代理调用日志可信；客户端上报的输入/最终回复属"尽力采集"，非防篡改审计。服务端身份从令牌解析、分组从库获取，**不信任客户端提交**。
- **P0 严格在线**：连不上服务器即禁用 Agent；不存在离线运行 Agent。
- **不破坏本机文件操作**：Agent 仍在用户本机运行，用户操作自己的文件，不引入文件上传/服务器文件语义。
- **数据本地化**：受管模型流量与集中记录不出内网。
- **知情同意可被服务端强制**：未取得对当前告知版本的有效同意，不得调用模型。
- **受管模式须在启动边界强制**：仅隐藏界面不够（本地存在可重新启用外部模型的配置面），必须在主进程/Agent 层强制。
- **数据治理（Intent 级硬约束）**：集中留存的原始输入与最终回复属敏感数据，须遵循访问最小化、查看/导出需正当使用目的、留存与删除可审计；须设定数据责任人与审批人（具体人选见 Open questions）。
- **遵循子仓库规则**：hydroZagent 客户端改动遵循其 `AGENTS.md` / `HYDRO.md`。
- **兼容既有会话数据**，改造不得破坏现有本地会话/项目数据与用户体验。
- **可回滚、可关闭（fail-closed）**：受管策略与采集初次上线需可观测、可回滚，避免误伤正常使用；但**回滚或关闭不得重新开放模型直连或无鉴权的局域网 Web 旁路**——宁可禁用功能，不可退回不安全状态。

## Out of scope

- **离线运行 Agent**：P0 不做；跨重启的加密持久化补传队列留待 P2。
- **实名审计**：P0 为自助注册 + 标注非实名，记录只代表"自报账号"，不作实名依据。
- **分组及其查询/统计/导出/管理界面**：属 P1，不在 P0。
- **按业务账号隔离本地目录**：P0 以"一机一账号"为环境假设与已知风险，不宣称客户端隔离；真正隔离放 P2。
- **macOS 发行**：P0 仅 Windows；macOS 纳入 P2，排期需先做构建与签名 Spike。
- **浏览器/Shell/扩展的联网出口管控**：不在应用强管范围，需运维层网络出口策略配合。
- **实现细节**：接口契约、数据库表结构、令牌机制、取消/错误码、部署拓扑等留给 spec.md。

## Success measures

**P0 可验证行为**（对照需求材料 §8 验收要点，spec 阶段细化为具体用例）：

- 未登录/离线无法调用模型；未同意当前告知版本时被服务端拒绝。
- 安装包与配置目录中不存在可直接调用模型的共享密钥；受管模式无法添加/切换其他 Provider。
- 模型服务拒绝非代理来源请求；代理与应用日志不记录请求正文与令牌。
- 伪造身份的上报被拒；重复上报可去重；只采集同意后的新轮次，不自动回传历史会话。
- 令牌撤销/账号停用后在用客户端及时失效；流式取消后上游同步终止、无悬挂请求。
- 局域网 Web 旁路被关闭并锁定。
- **采集为"尽力采集、失败对用户可见"**，且**采集完整率可观测**——以服务端模型调用日志为基线对照客户端使用记录的关联覆盖率。

**产品效果指标（衡量内部试用是否成功，目标值见 Open questions）**：

- 试用人数与试用周期。
- 登录后模型调用成功率。
- 客户端使用记录与可信模型调用日志的**关联覆盖率**。
- 上报失败率与其中用户可见失败率。
- 管理员能否利用记录完成实际质量分析（定性验证）。
- 试用期内是否发生密钥泄漏、未授权调用或内网外传事件（期望为零）。

## Open questions

**P0 试用前须确定：**
1. 默认使用记录保存期限的具体值与自动清理策略。
2. 默认令牌有效期与刷新策略。
3. 模型服务网络隔离的具体方案：如何确保内网模型仅接受代理服务器请求。

**数据治理（需产品负责人/单位明确）：**
4. 数据责任人与审批人是谁。
5. 原始输入/最终回复的数据分类级别，及管理员查看/导出的正当使用目的与审批方式。
6. 是否需要超出当前采集边界的敏感信息最小化/脱敏处理。

**产品指标目标值（需产品负责人明确）：**
7. 试用周期与目标试用人数。
8. 登录后模型调用成功率目标、客户端记录与模型调用日志的关联覆盖率目标、可接受的上报失败率上限。

**技术设计阶段补齐：**
9. 容量估算所需的单位实际用户数、日均轮次、期望保存年限。
10. macOS 构建与签名 Spike 的结论与排期。
